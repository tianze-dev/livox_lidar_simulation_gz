# 0.1.0 首版交付检阅

日期：2026-10-09。定位是基于 RGL 的非官方 Livox 多型号 Gazebo／ROS 2 仿真套件。本文件是交付检阅入口，不是已经公开发布的公告。

## 检阅顺序

1. 按 README 在独立工作空间准备缓存并构建，或使用 docker/Dockerfile 构建干净容器。
2. 检查 MID-360 精细模型近景、单实例点云以及双实例隔离。
3. 运行 `moving:=true`，查看真实关节反馈驱动的动态 TF；运行移动验证脚本检查几何和 IMU。
4. 运行 `model:=avia name:=avia`，确认型号切换不复制扫描插件，并阅读其近似外参／简化外观限制。
5. 执行 `bash scripts/check.sh --gpu` 与 `python3 scripts/release_check.py`；长时项另执行 `--endurance`。
6. 阅读支持矩阵、第三方声明和未覆盖范围后，再决定是否建立远程仓库、发布标签和正式 release。

## 交付内容

- 静态、双实例和移动验证场景；MID-360 精细材质模型及可复现导出／修复工具。
- MID-360／Avia 配置、固定上游版本与下载哈希，标准 PointCloud2／IMU／TF 接口。
- 安装、运行、单元与 GPU 检查入口，CPU 容器 CI 配置。
- 中英文 README、支持矩阵、接入／排错说明、许可和第三方来源。
- 可复现运行测试及性能 JSON 记录；机器可读汇总见 [first_delivery.json](results/first_delivery.json)。

## 验证记录

本机环境为 Ubuntu 24.04、ROS 2 Jazzy、Gazebo 8.15.0、RTX 4060／580.178.04。系统依赖和本包均在不加载其他机器人工作空间的条件下使用。

| 项目 | 结果 |
|---|---|
| 单元测试 | 43 项通过 |
| MID-360 单／双实例 | 字段、频率、TF、墙面、暂停／步进／复位通过 |
| MID-360＋Avia 混合实例 | 两路点云／IMU、独立 TF、唯一时钟、墙面改位及复位通过 |
| MID-360 移动夹具 | 10 秒测量段，墙面误差 p95 约 0.582 mm，陀螺 z=0.15 rad/s；动态 TF 与关节反馈一致，复位后恢复 |
| Avia 移动夹具 | 6 秒视场仍覆盖墙面的测量段，p95 约 0.458 mm；动态 TF、理想 IMU 和复位通过 |
| MID-360 300 秒稳定性 | 2971 帧，仿真频率 10 Hz，墙钟接收约 9.906 Hz，实时倍率约 0.991；进程组 RSS 从约 612 MiB 到 615 MiB，后段稳定 |
| Avia 60 秒稳定性 | 593 帧，仿真频率 10 Hz，墙钟接收约 9.897 Hz，实时倍率约 0.990 |
| 干净容器 | 从摘要锁定的 ROS base 安装依赖、下载缓存、构建、43 项单元测试，以及整个 GPU 检查套件通过；未挂载宿主工作空间 |
| 无 GPU 容器负向检查 | 环境检查明确返回失败，未假装仿真可运行 |
| 发布元信息检查 | 结构／资源检查通过；维护者沿用 Git 身份的待确认提示保留 |

上述几何误差是理想测试墙和给定轨迹的结果，不是实机雷达精度。动态几何验证使用独立关节反馈，而不是以自瞄／定位算法输出判断。Avia 超过该轨迹时长可能转离墙面，因此不能把“墙面点减少”误当求交失败。

资源测量中 RSS 是进程组聚合，不是去重 PSS；GPU 利用率及显存为全设备数值，包含其他图形应用。额外 30 秒样本记录了进程组生命周期平均 CPU 百分比，不是瞬时或独占基准。未做 24 小时测试，也没有第二台物理机器的结果。

容器验证镜像 ID、基础镜像摘要和系统包版本保存在机器可读汇总中。GitHub workflow 文件已提供并在本地以同一 Dockerfile 验证；尚未推送远程或声称 GitHub 托管任务已实际执行。

## 必须保留的边界

- Avia 为扫描／接口预览，不能以“上游有预设”宣称型号已完整复现。
