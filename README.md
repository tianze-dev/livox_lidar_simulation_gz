# Livox LiDAR Simulation for Gazebo

基于 RGL 的非官方 Livox 多型号 Gazebo／ROS 2 仿真套件。

面向 ROS 2 Jazzy 和 Gazebo Harmonic，复用 RGL 的扫描后端与 Gazebo 插件，按型号配套外观模型、碰撞体、安装坐标和传感器配置，提供标准 PointCloud2／IMU 输出、独立演示及机器人接入方式。项目重点是易用、完整和可复现，不重新开发射线引擎，也不宣称比上游更高的物理真实性。

**当前状态：开发准备阶段。已登记参考基线并提供环境检查脚本，尚未迁入插件、模型或启动程序，不能直接运行仿真。**

完整任务、技术边界和验收标准见 [开发计划](DEVELOPMENT_PLAN.md)。

开发与提交规则见 [贡献规范](CONTRIBUTING.md)。本地 Git 已初始化；尚未配置远程仓库或发布。

已核查环境、源码差异、资源指纹和首批任务见 [开发准备记录](docs/DEVELOPMENT_READINESS.md)。运行 `bash scripts/check_environment.sh` 可重新检查基础开发环境；它不安装依赖，也不代表 GPU 仿真已经通过。

## 已确定方向

- 首先支持 Ubuntu 24.04、ROS 2 Jazzy、Gazebo Harmonic；运行 RGL 需要兼容的 NVIDIA GPU。
- 作为独立仓库开发、构建和测试；原工程只作为历史代码与资产来源，不是开发环境或运行依赖。
- 先完成 MID-360 的独立化和验收，再以 Avia 检验多型号架构，随后扩展其他型号。
- 本期采用整帧快照扫描，保留帧时间戳、统一仿真时钟和 TF；不实现帧内运动畸变。
- 自定义逐点时间、历史位姿采样与插值，和 Livox CustomMsg 转换、FAST-LIVO2 接入一起暂缓，后续统一规划；不迁入对应增强代码或创建适配包、算法示例目录。
- 优先复用 RGL Gazebo 上游已收录的二进制扫描预设；本项目的 CSV 转换工具留待后续，不作为首版前置任务。
- 后续由哨兵、无人机等父项目通过 Git 子模块接入；通用改动只在本仓库维护，父项目固定并主动更新子模块版本。
- 对每个型号分别说明扫描预览与标准接口的验证程度；算法集成和实机对照另行规划。

## 本项目负责的交付

- 按型号配套模型：可视网格与材质、简化碰撞体、尺寸和安装基准、测量原点、必要的 IMU 外参，以及参数与资产来源。
- 统一型号配置和标准 ROS 2 接口，复用已有发布能力，只补齐缺失的适配。
- 提供独立 Gazebo／RViz 演示、挂载到用户机器人的示例和多实例配置。
- 固定依赖与预设版本，提供资源校验、安装检查、缓存和明确的故障提示。
- 逐型号验证并公开支持矩阵、限制、可复现测试与第三方声明。

## 独立开发与子模块接入约定

拟定仓库根目录直接作为 `livox_lidar_simulation_gz` ROS 包，未来可作为子模块放入任意父工作空间的 `src/`。当前尚未创建包构建文件，该结构是后续实现约定。

本包只依赖公开声明的 ROS／Gazebo／RGL 及系统依赖，不加载哨兵或无人机工作空间，不查找它们的源码、缓存或安装产物，不假设固定父目录。测试使用独立工作空间和本包提供的最小示例。

通用模型、扫描配置、标准接口和传感器启动入口属于本包；具体机器人的安装位姿、话题重映射、场地及整机启动编排属于父项目，通过参数、Xacro 和 launch 接口接入。传感器入口不强制启动额外 Gazebo 世界或 RViz，独立演示另提供入口。

修复在本仓库提交并发布后，各父项目更新到指定提交或标签，并提交自己的子模块指针。子模块不会自动追踪最新提交；可共享同一修复，但每个工作空间仍需重新构建和完成集成验证。当前不创建远程仓库，也不修改父项目的子模块配置。

本机已有 MID-360 STL 和配色后的 Blender／GLB 资产，尚未迁入本仓库；其他型号的配套模型仍待整理。Livox 官方仿真仓库已有 MID-40 网格，官网也提供部分产品的 CAD；本项目的工作是按型号整理、转换、补充和验证，不把官方资产宣称为原创模型。上色仅用于外观，不代表雷达光学标定。
